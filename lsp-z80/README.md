# lsp-z80

`lsp-z80` is a small, dependency-free Language Server Protocol server for Z80 assembly written for the Pasmo assembler dialect.

Pasmo is intentionally the only implemented dialect. The language-specific behavior is behind one dialect interface so additional syntaxes can be added later without duplicating workspace indexing or protocol handling.

This directory is a top-level subproject of Z80 Digital Twin. It retains its
own package, tests, and stdio process boundary so language analysis remains
usable without building or running the emulator.

## Current capabilities

- standard `Content-Length` framed JSON-RPC over stdin/stdout
- full-document synchronization with document versions
- Pasmo and documented Z80 diagnostics
- canonical `$`-prefixed hexadecimal warnings and replacements
- completion for instructions, directives, registers, and symbols
- instruction, directive, register, literal, and symbol hover
- document and workspace symbols
- definition, references, document highlights, and conservative rename
- semantic tokens and folding ranges
- workspace indexing, source includes, predefined symbols, and include paths
- configurable diagnostic severity

The server never runs Pasmo, source macros, build scripts, or other external commands.

## Run from a checkout

Using the project interpreter:

```sh
PYTHONPATH=src .venv/bin/python -m lsp_z80
```

After installing the package, editors can invoke:

```sh
lsp-z80
```

The process reads LSP messages from stdin and writes protocol messages to stdout. Logs go only to stderr.

## Initialization options

```json
{
  "dialect": "pasmo",
  "includePaths": ["/absolute/path/to/includes"],
  "predefinedSymbols": ["DEBUG", "TARGET_Z80"],
  "diagnostics": {
    "pasmo.non-standard-hex": "warning",
    "pasmo.undefined-symbol": "error"
  }
}
```

Diagnostic values are `error`, `warning`, `information`, `hint`, or `off`. Any dialect other than `pasmo` is rejected during initialization.

## Canonical hexadecimal notation

The canonical form is `$` followed by hexadecimal digits:

```asm
ld a,$2a
ld hl,$8000
```

Other hexadecimal forms accepted by Pasmo remain valid input but receive `pasmo.non-standard-hex` with their canonical spelling.

Mnemonics, directives, registers, and hexadecimal digits generated by the server
use lowercase. Source recognition remains case-insensitive, so existing uppercase
or mixed-case files continue to work unchanged.

